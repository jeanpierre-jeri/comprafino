# Database

Lazy Drizzle/Neon HTTP client; importing opens no connection. Schema: retailers, retailer listings, meaningful price history, ingestion runs and derived listing normalizations. Generate with `pnpm db:generate`, review SQL, and explicitly apply with `pnpm db:migrate` using root `.env`/`DATABASE_URL`. The first migration seeds all three retailer identities. No migrations run on build/startup. The applied Neon constraints/indexes match the migration.

Persistence validates listings, uses one atomic HTTP batch and serializes by retailer row lock. Equal/older observations are ignored; unchanged fresh observations update last-seen without appending history. All ingestion writers must follow the same retailer-lock convention at PostgreSQL’s default READ COMMITTED isolation. The partial unique index independently prevents multiple current states. Run records have separate transaction boundaries.

`pnpm test` runs credential-free unit tests. `pnpm test:integration` at the repository root runs uncached Vitest PostgreSQL tests with an explicitly exported `TEST_DATABASE_URL`; absent configuration clearly skips the suite. Tests never load `.env` or use `DATABASE_URL` as a fallback. Prefer a dedicated Neon test branch/database. The role must be able to create schemas. Each suite applies the journaled migrations to a random `comprafino_test_…` schema (qualifying its foreign keys there), adds transaction-local search paths without a public fallback to the real Drizzle/Neon batch, and removes only that schema in teardown. Abrupt termination may leave a test schema for manual review; there is no broad cleanup of other schemas or tables.

Verified controlled tests cover unchanged freshness, 1290/1490 → 1090/1490 history transitions, equal/stale replay, rollback after an isolated test-only history constraint fails the final insert, and simultaneous initial/changed observations. They do not modify real retailer listings. See [Tottus integration](../../docs/retailers/tottus.md) for separate live evidence.

`pnpm normalize:catalog -- --retailer=metro --limit=50` normalizes existing listings through core and persists queryable derived attributes separately. `--dry-run` reads PostgreSQL but writes nothing. Root `.env` is loaded only by the CLI; importing remains lazy. Bound 1–5000 (default 100); retailer filter optional. Unchanged runs preserve normalization timestamps. Input guards skip stale snapshots using the same retailer locks as ingestion. No prices/history are modified. Four added PostgreSQL tests cover recomputation/idempotency, stale/concurrent writes, rollback and derived SQL constraints. See [catalog normalization](../../docs/catalog-normalization.md).
