# Database

Milestone 19B adds `user_shopping_lists` and `readUserShoppingList` / `mutateUserShoppingList`, with validated JSONB, one document/user, insert-only first-write CAS, conditional positive-revision updates, fresh conflict reads and read-only missing-item removals. Migration 0010 is generated for review, not applied to an application database. See [persistence backend](../../docs/shopping-list-persistence.md).

Lazy Drizzle/Neon HTTP client; importing opens no connection. Schema: retailers, retailer listings, meaningful price history, ingestion runs derived listing normalizations, canonical products and canonical associations, plus Better Auth user/session/account/verification models. Generate with `pnpm db:generate`, review SQL, and explicitly apply with `pnpm db:migrate` using root `.env`/`DATABASE_URL`. The first migration seeds the original three retailer identities; `0011_real_quasar.sql` expands the retailer constraint and seeds Makro. No migrations run on build/startup. Repository state does not verify remote migration status.

Milestone 19A generated `0009_grey_husk.sql` for review without applying it to an application database. Auth row IDs/user FKs use supported UUID types/defaults; email and session tokens are unique, provider/subject pairs have composite uniqueness, and user deletion cascades to sessions/accounts. Auth configuration/handlers and PostgreSQL-backed session tests belong to `apps/web`. No shopping-list tables were added. See [auth setup and schema review](../../docs/auth.md).

Persistence validates listings, uses one atomic HTTP batch and serializes by retailer row lock. Equal/older observations are ignored; unchanged fresh observations update last-seen without appending history. All ingestion writers must follow the same retailer-lock convention at PostgreSQL’s default READ COMMITTED isolation. The partial unique index independently prevents multiple current states. Run records have separate transaction boundaries.

`pnpm test` runs credential-free unit tests. `pnpm test:integration` at the repository root runs uncached Vitest PostgreSQL tests followed by web auth Playwright handler tests with an explicitly exported `TEST_DATABASE_URL`; absent configuration clearly skips the suite. Tests never load `.env` or use `DATABASE_URL` as a fallback. Prefer a dedicated Neon test branch/database. The role must be able to create schemas. The test database must already have pg_trgm from the reviewed migration; isolated tests exclude extension creation and qualify only public.similarity(), keeping shared extension objects unchanged. Each suite applies the journaled migrations to a random `comprafino_e2e_…` schema (qualifying its foreign keys there), adds transaction-local search paths without a public fallback to the real Drizzle/Neon batch, and removes only that schema in teardown. Abrupt termination may leave a test schema for manual review; there is no broad cleanup of other schemas or tables.

Verified controlled tests cover unchanged freshness, 1290/1490 → 1090/1490 history transitions, equal/stale replay, rollback after an isolated test-only history constraint fails the final insert, and simultaneous initial/changed observations. They do not modify real retailer listings. See [Tottus integration](../../docs/retailers/tottus.md) for separate live evidence.

`pnpm normalize:catalog -- --retailer=metro --limit=50` normalizes existing listings through core and persists queryable derived attributes separately. `--dry-run` reads PostgreSQL but writes nothing. Root `.env` is loaded only by the CLI; importing remains lazy. Bound 1–5000 (default 100); retailer filter optional. Unchanged runs preserve normalization timestamps. Input guards skip stale snapshots using the same retailer locks as ingestion. No prices/history are modified. Four added PostgreSQL tests cover recomputation/idempotency, stale/concurrent writes, rollback and derived SQL constraints. See [catalog normalization](../../docs/catalog-normalization.md).

`pnpm match:catalog -- --limit=500` derives cross-retailer canonical groups; `--dry-run` leaves associations untouched. `pnpm match:evaluate` scores 66 reviewed real fixture pairs with PostgreSQL pg_trgm. Both use root `.env`/`DATABASE_URL`. Canonical persistence shares stable retailer locks, guards current raw/normalized snapshots, protects manual/split groups and avoids unchanged writes. Listing primary key, per-canonical retailer uniqueness and a composite listing/retailer foreign key enforce identity boundaries. Recompute after fresh normalization; no original listing or price state is merged/deleted. See [catalog matching](../../docs/catalog-matching.md).

`pnpm match:audit` separately validates and scores the 105-pair independent audit fixture (34 newly automatic pairs, 30 reviews, 30 rejects and eleven targeted contrasts), without changing canonical associations. The original `match:evaluate` calibration/holdout report stays separate. The expanded sample requires a complete matching scope such as `--limit=1000`; the global default 100 now samples only one retailer. The frozen matcher remains unchanged. See [independent audit](../../docs/catalog-matching-audit.md).

Public reads use `searchCanonicalProducts(db, query)` and `getCanonicalProductComparison(db, id)`. They join existing trusted automatic/current-version associations to active ordinary open price-history states, require two usable retailers, validate returned values, and return product/offer data without matching diagnostics. Search is token-preserving and bounded to twenty results; pg_trgm ranks admitted results. Each function performs one aggregate batch; no public request writes or runs matching. See [public search](../../docs/public-search.md) for price/tie/freshness semantics and local validation.

`pnpm audit:staples` runs a read-only, fixed ten-query generic/exact relevance audit against root DATABASE_URL, reporting public source category/title/quantity/price data, demand and a history digest. Labels and precision are reviewed independently, not inferred from the production classifier. Family evidence is recomputed from current listing snapshots during generic/combined search and developer inspection; no schema/migration or matcher change is involved. Specific remaining query tokens and lexical fallback are retained. See [staple coverage](../../docs/staple-coverage.md) for boundaries and before/after evidence.

Milestone 11 adds the reviewed `retailer_listing_offers` current-state migration. Shared listing ingestion atomically synchronizes concrete benefits without changing ordinary price history. Unchanged offer rows inherit verified listing freshness. Apply the migration and deploy readers/ingestion together; see [conditional pricing](../../docs/conditional-pricing.md).

Production `client.ts` has only Neon HTTP transport. Explicit lifecycle/schema/local transport helpers live in `src/testing/`; `pg` is test-only (dev dependency). Domain integration files own their schema and reset/reseed before each case, including deliberate transaction/race tests. HTTP handler tests and benchmark wiring live in `apps/web/testing`, with DB fixtures kept here. Controlled browser servers use an explicit test-only HTTP preload, not a production environment-mode branch. See [test ownership](../../docs/local-testing.md#test-ownership-and-state).
